## 异常处理

### 为什么需要这个异常处理呢？

#### Java 中的异常

在 Java 中，异常实际上是分两类的：一种是 Error，一种是 Exception。对于 Error，它一般是指一些无法避免的错误，比如栈溢出、虚拟机内存溢出等。对于这一类，我们没有办法解决，只能出现后再调整。

另一类是 Exception，它又包含两类：

1. 运行时异常。
2. 编译时异常。

对于编译时异常，编译时异常：
程序在编译时就会报错。如果出现这个错误，编译无法通过，程序就无法运行起来，这个就不多说。

运行时异常：
另一种是运行时异常，指程序运行过程中出现的一些异常，比如数组越界、空指针。还有我们预期的异常。

#### 全局异常处理。

对于这个运行时异常，如果我们不做处理的话，在 Spring 框架中，它会直接将这个报错呢透传给前端，也就是出现一个 500 的一个请求错误。

为了避免这种情况出现，也就是让前端直接看到我们的报错，我们需要对它做统一处理。

也就是说，这里要让异常也返回我们设定好的响应格式。因此，我们需要一个全局异常处理：对于程序运行中出现的运行时异常，我们将其捕获，并返回一个设定好格式的响应。

这是全局异常处理。

所以，这是全局异常处理的其中一个作用。也就是说，它能统一响应，包括异常抛出时的响应。

对于预想中的异常，一般处理方式是使用 try catch。但如果每一个运行异常都要放在 try catch 里，就会显得比较麻烦。所以这里我们做一个全局集中处理：如果它抛出了异常，就在全局异常处理这里捕获它，然后给出我们设定的响应结果，给到前端或客户端。

这里是它的第二个作用：减少 try catch 的数量。

#### 自定义异常与错误码

对于这个预想中的异常，我们会把它叫做业务异常。对于这种异常，我们会单独自定义出来，其中要包括它的错误码和错误信息。然后在全局异常中对它进行单独处理。

对于这个错误码，我们也要对它进行自定义，以此区分我们设定的预想异常类型。

同时，对于抛出异常，我们可能会在 if 条件中、if 块中每次都 throw 这个异常。

对于这种重复模式，我们可以将其封装为一个工具类，专门用于抛出异常。

## 基础响应类

为什么需要一个基础响应类？

如果不做这件事，前端收到后端的响应通常就是数据。对于这个响应，我们根本不知道它是否正确、是否成功，也不知道响应数据的类型。

为了前后端方便，需要后端设定一个所有响应都遵守的响应模板。

在这个基础响应类中，我们需要有代码、响应、响应码、响应信息和响应数据。

每一个 Controller 中的响应，都通过这样一个基础响应类包装起来。

## page分页对象

这里对于分页对象，我们在做分页时，需要在参数中传递当前第几页、一页有多少条、行数总数等分页的一个参数。

将这些参数写入vDTO中不太好。我们单独创建一个类，作为所有类分页功能的父类。其他类可以继承这个父类。继承后，这些类就自动拥有分页参数，无需在每个类中单独定义。

除此之外，还有删除类，这个类只需要id作为参数

## 项目结构

对于项目的结构，我一般都是遵循 controller、service、mapper 三层。如果有需要的话，可以增加 application 这一层，或者再增加一个 manager 这一层。

## 跨域

对于跨域这一块呢，一般都是后端的去给前端去放开啊，所以这里的话就可以直接把跨域的代码呢写到这里来。

## starter

对于上述提到的这些呢，我们都可以通过starter来去将其维护成一个固定的starter，以后如果说要初始化一个项目，直接将这个给引入即可。

但是呢，还有这个项目结构需要我们去处理，所以我们同样可以再搞一个模板项目，将这个starter给引入，那么以后我们需去新建一个项目的时候我们只需要使用这个模板仓库在GitHub上新创建时呢，使用这个模板一次生成即可。

对于Starter 在其他电脑环境使用呢，我们可以使用jitpack这个开源项目。
